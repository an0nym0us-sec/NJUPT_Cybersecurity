# ctf.show - web2 最简单的SQL注入 WriteUp

## 题目信息
- 平台：ctf.show
- 方向：Web
- 难度：入门

## 解题过程
1. **信息搜集**：查看网页源代码，确认前端没有JS校验，漏洞在后端。
2. **绕过尝试**：初始尝试常规的 `admin' or 1=1#` 无法绕过后端逻辑校验。
3. **获取Flag**：根据WP提示，利用 `UNION SELECT` 联合查询。构造Payload（示例：`username=admin' or 1=1 union select 1,flag,3 from flag#`），通过 F12 抓包修改请求体绕过前端限制，成功在页面回显中获取到Flag：`ctfshow{366e3930-68f5-4952-9f65-511b6853086f}`。

## 原理分析（核心考点）
这道题的核心是**联合查询注入（Union-Based SQL Injection）**。
数据库规定 `UNION SELECT` 前后的列数必须一致。假设原SQL查询有3列，那么 `1, flag, 3` 中的 `1` 和 `3` 只是“占位符”，真正的目的是把原本回显用户名的“第2列”替换成我们要查的 `flag` 字段。这样服务器就会把数据库里的flag打印到网页上。

## 经验总结
- 面对复杂的注入，不要只会 `or 1=1`，要学会看报错、猜列数。
- 前端输入框有过滤或长度限制时，要熟练使用 F12 网络面板抓包并重放修改请求。
